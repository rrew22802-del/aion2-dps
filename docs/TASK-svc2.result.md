# Отчёт svc2 / 2.6.1

## Party roster

- Пакет `45 36` подключён к roster: ID читается varint с payload offset 2, существующий парсер извлекает имя и job/class, повторная запись обновляет поля участника. Главный персонаж добавляется из `33 36`; его флаг `inParty` остаётся `true` даже при пустом roster.
- Добавлена ограниченная память списка группы (24 ID), timestamp последнего изменения и операции удаления участника/очистки группы. Смена главного персонажа очищает прежний список; боевой reset сохраняет roster.
- `45 37` обрабатывается как выход с varint ID по смещению 2; `45 38` очищает группу, оставляя главного персонажа. Эти действия — предварительная интерпретация сырых opcode-контекстов: захваты не позволяют независимо подтвердить границы сообщений и поле ID для `45 37`. Подробности и примеры записаны в `docs/PACKETS-party.md`.
- Alliance-список не выделяется отдельно: подтверждённого alliance-поля или отдельной roster-структуры в просмотренных данных нет.

## API и история

- `GET /v1/party` возвращает `{members:[{id,name,class}],updatedAt}`.
- `inParty` добавлен в player rows `/v1/state`, player details/fight summaries и архивные записи/строки `/v1/history`. Неизвестные игроки получают `false`, главный персонаж — `true`. ID roster сохраняются вместе с архивным боем.
- Обновлена документация `docs/SERVICE-API.md`, добавлена заметка о packet evidence в `docs/PACKETS-party.md`.
