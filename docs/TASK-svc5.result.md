# Результат svc5 — 2.8.0

## Реализовано

- `players[].damageTaken` добавлен в текущий `/v1/state`, `/v1/history` и архивный `/v1/history/{fightId}`. Игроки, известные только как получатели урона, также включаются в сводку. `GET /v1/fights/{fightId}/taken?player={id}` отдаёт сумму и разбивку по источнику/NPC/skill code.
- `GET /v1/fights/{fightId}/deaths` отдаёт смерти `00 8D` с последними десятью событиями урона/лечения на игрока. Кольцо ограничено 10 событиями × 2 000 игроков; до 128 смертей на цель.
- `GET /v1/fights/{fightId}/buffs` агрегирует интервалы каждого игрока по skill code, uptime, числу сохранённых применений и известным ID источников. Uptime ограничен окном боя в 20 минут; интервалы используют существующие caps хранилища.
- `GET /v1/fights/{fightId}/boss-casts` сообщает skill code и время пакета для источников, уже опознанных парсером как NPC. Это наблюдение damage-пакета, не оценка начала анимации каста.
- В строках `/v1/history` добавлен `mapId`. Сейчас он `null`: подтверждённого dungeon/map identity пакета в изученных документах и захватах нет.
- Версия обновлена до 2.8.0 в Cargo, lockfile, Tauri и `package.json`; обновлены `CHANGELOG.md` и `docs/SERVICE-API.md`. Добавлен `docs/PACKETS-svc5.md` с источниками данных, caps и ограничениями.

## Проверка и ограничения

- Добавлен unit-тест HP decoder на фактическом zero-HP примере `00 8D` из захвата. `cargo test --manifest-path src-tauri/Cargo.toml` запустить не удалось: `cargo` не установлен.
- Остальные `04 38`/`2A 38`/`2B 38` decoder paths повторно используют существующие парсеры. Проверенные `.aetherpc` содержат TCP chunks, а совпадения opcode в raw bytes не подтверждают цельные расшифрованные сообщения; поэтому тестовые байты для этих parser paths не выдумывались. Для полного требования по capture-fixtures нужно сохранить изолированные декодированные сообщения от live dispatcher.
- `git diff --check` завершился без ошибок whitespace. Изменённые Rust участки перечитаны вручную; локальная Rust-компиляция недоступна.
