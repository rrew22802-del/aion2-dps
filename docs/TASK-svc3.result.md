# Результат svc3 / 2.6.2

## Что изменено

- Для Npcap время жизни цели обновляется только пакетами с игровым magic в направлении сервер → клиент. Если таких пакетов нет восемь секунд, пишется `capture target stale`, останавливается текущий захват и запускается параллельное сканирование всех доступных адаптеров. Найденный поток может иметь другой IP и порт.
- Поток определяется полным направленным набором IP и портов. На выбранном адаптере новые потоки проверяются без полного сканирования; после трёх серверных magic-пакетов каждый получает собственные TCP reassembler и assemblers.
- Неизвестные потоки попадают в ограниченный отрицательный кэш и отбрасываются до TCP reassembly. Это не создаёт stream assembler и не вызывает сообщения о stalled/resync для HTTPS и других посторонних потоков. Magic-пакет снимает поток с игнорирования и начинает его распознавание.
- Причина очистки `cleaned stale assembler ports` — простой свыше 30 секунд; проверка выполняется в цикле memory snapshot. Поток текущей цели сохраняется: частичные TCP и stream буферы сбрасываются, а сам поток и его assembler не удаляются.
- Строки `dispatcher packet …` переведены с INFO на DEBUG.
- Версии Cargo, Tauri и приложения обновлены до `2.6.2`; добавлены запись CHANGELOG и этот отчёт.

## Регрессионные тесты

Добавлены тесты на клиентский keepalive без обновления серверной свежести, различение направлений, захват нового игрового потока после трёх magic-пакетов и отбрасывание HTTPS-потока до сборки.

Тесты и Rust-сборка локально не запускались: Cargo в среде отсутствует; компиляция остаётся проверкой CI.
